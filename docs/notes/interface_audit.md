# Interface audit — 2026-09-04

## Evidence

The fixtures were regenerated by the official installed engine, not assembled
from an assumed schema:

```powershell
.venv\Scripts\python.exe scripts\inspect_obs.py --max-games 12 --seed 20260904
```

`fixtures/live_capture_manifest.json` records the package/spec versions,
episode statuses and rewards, decision locations, and a canonical-JSON SHA-256
for every dump. The captures cover:

- the initial deck observation (`select is None`);
- a MAIN decision;
- a real multi-select with `maxCount > 1`;
- an observation containing an attached EnergyType value.

The capture run used `kaggle-environments==1.32.7`, cabt spec `1.0.0`, and
finished `DONE/DONE` with a normal zero-sum reward pair.

A post-change entrypoint smoke test using exactly
`env.run(["submission/main.py", "random"])` also finished `DONE/DONE`, reward
`[1, -1]`, with remaining overage times approximately `599.971 s` and
`600.000 s` (one game; legality smoke only, not a win-rate estimate).

## Confirmed contract

- Deck phase: return exactly 60 integer card IDs.
- Battle phase: return a `list[int]` of exactly `select.maxCount` distinct
  indexes, each in `[0, len(select.option))`.
- Live cabt guarantees `maxCount <= len(option)`. Clamping an action to fewer
  indexes is not a legal fallback; the submission wrapper instead treats an
  impossible observation as an engine-contract violation.
- Successful terminal episodes have statuses `DONE/DONE` and rewards from
  `{-1, 0, 1}` as either a win/loss pair or a draw pair.
- A framework-disqualified player is different: live invalid-deck and
  invalid-selection probes report that player's terminal reward as JSON null.
  The opponent is respectively left at reward `0` (failure before battle
  start) or awarded `1` (invalid battle selection). Evaluation must classify
  `INVALID` from status before interpreting reward.

## Adapter findings

- Live `Pokemon.energies` values are integer EnergyType IDs (for example
  `[3]`), not card dictionaries. The shared type annotation was corrected.
- Special Conditions live on `PlayerState`; the adapter now mirrors them onto
  the canonical Active Pokemon's convenience list.
- Nullable list containers are normalized to empty lists where the canonical
  type requires a list. Newly appended, unknown engine fields remain available
  through `CanonicalState.raw` and `PokemonView.raw`.
- Unknown future selection/option enum values are described as `UNKNOWN_<id>`
  rather than rejected.

Tests in `tests/test_adapter.py` verify fixture provenance, perspective mapping,
nullable/unknown fields, multi-select count, type, uniqueness, and bounds.
`tests/test_contract.py` additionally executes the installed official engine to
lock its specification and successful/invalid terminal behavior.
